# Anthelios — Protection, In Motion

Apple-style scroll-scrubbed image sequence for La Roche-Posay Anthelios, built from the
Figma "Dark" design (desktop + mobile Option 2) and the 851-frame LRP render.

## Run

```bash
npm install
npm run dev        # http://localhost:3000
npm run build && npm start
```

Append `?hud=1` to the URL (or press `h`) for the dev HUD: current scene, local progress,
source frame, decimated frame index, and loaded-frame count. Use it to tune `src/lib/scenes.ts`.

## How it works

```
Nav (fixed)                      – hides on scroll-down past the hero, returns on scroll-up
Stage (TOTAL_SCROLL + 1 screens) – sticky 100svh viewport containing:
  ├─ <canvas>                    – draws the nearest decoded frame, cover-fit, DPR ≤ 2
  ├─ one overlay per scene       – opacity/translate driven from scroll (no React re-renders)
  ├─ "Scroll to explore" cue     – hidden from the UV scene on
  └─ loading bar                 – hides once the first 40 frames are decoded
Footer (in flow)
```

- `src/lib/scenes.ts` — the scene map. Each scene has a source-frame range (`frames`, in the
  original 0–850 numbering), a scroll length in viewport heights (`scroll`), and optional
  fade settings. Each scene maps its own scroll band to its own frame range, so captions stay
  aligned with the footage no matter how long a scene is.
- `src/lib/frameLoader.ts` — progressive loader: first band in order, then a coarse pass across
  the whole sequence (every 32nd, 16th, 8th…), then the rest. `focus()` pulls frames near the
  current scroll position forward. Frames are `<img>` elements so the browser manages decoded
  memory.
- `src/components/Stage.tsx` — ScrollTrigger reports progress, a ticker eases toward it, and
  one `update()` draws the canvas and sets each overlay's `opacity` + `--reveal`.
- `src/components/overlays/sceneOverlays.tsx` — which copy/markup each scene shows. Copy is
  verbatim from Figma; see the TODO at the top for the three suspected typos.
- Smooth scrolling: Lenis on wheel, native on touch, off under `prefers-reduced-motion`.

## Frames

`public/frames/` is generated by `scripts/build-frames.mjs` from `../LRP_renders/Frames/`
(2880×1620 JPGs, the flattened render — the PNG sequence is the transparent layer only):

```bash
node scripts/build-frames.mjs          # skips frames already built
node scripts/build-frames.mjs --force  # rebuild everything
```

| tier  | size      | crop        | served to                                    | total   |
| ----- | --------- | ----------- | -------------------------------------------- | ------- |
| m810  | 810×1440  | 9:16 centre | phones (≤767px)                              | ~7.2 MB |
| d1280 | 1280×720  | full frame  | non-retina ≤1400px (most laptops)            | ~8.2 MB |
| d1920 | 1920×1080 | full frame  | retina ≤1599px, non-retina 1401–2199px       | ~14 MB  |
| d2560 | 2560×1440 | full frame  | retina ≥1600px, any screen ≥2200px           | ~20 MB  |

Each device downloads one tier only. `src/lib/tier.ts` defines the tiers as media queries,
used both by `<link rel="preload">` tags in the HTML head (the first 6 frames, fetched before
JS boots) and by the loader, so the preloaded frames are reused, never fetched twice. Browsers
with data-saver on get one tier lower. The canvas is capped at the frame's own resolution, so
retina screens don't spend fill rate upscaling.

Quality is q70 (q72 for d1280): measured within 0.002 SSIM of q78 on this footage at 20% fewer
bytes. `STEP = 2` keeps every 2nd source frame; scroll scrubbing doesn't need 50fps density.
All of it is constants at the top of the script.

## Fonts

The design uses **Locator Light / Medium**. Inter is the stand-in. When the Locator web
files are licensed, drop them in `src/app/fonts/` and switch the loader in
`src/app/layout.tsx` (there's a commented `localFont` block ready). Line breaks in the
headlines were set for Locator's widths and may need a glance afterwards.

## Deploy

The app is a static export (`output: "export"` in `next.config.ts`): `npm run build` writes
plain HTML/JS/CSS plus the frames to `out/`. No Node server or Next adapter is needed.

Hosted on **Cloudflare Workers** (static assets, no Worker script) from the GitHub repo
(`Rishavmotion/LRP`), so every push to `main` redeploys. `wrangler.jsonc` points the Worker at
`./out`; its `name` must match the Worker's name in the Cloudflare dashboard. Project settings:

| setting        | value                       |
| -------------- | --------------------------- |
| Build command  | `npm run build`             |
| Deploy command | `npx wrangler deploy`       |
| Root directory | `/`                         |
| Node version   | `22` (from `.node-version`) |

To deploy from a laptop instead: `npx wrangler login`, then `npm run build && npx wrangler deploy`.

`public/frames` (~25 MB, 852 files) is committed so the build needs no render access. Keep the
source renders (`../LRP_renders`, `../klime png sequence`) out of git — see `../.gitignore`.
